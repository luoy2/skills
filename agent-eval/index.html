New model dropped. Switch or stay? 新模型出来了，换不换？

Test it on your own problems. agent-eval turns the moments you corrected your agents into an eval, reruns them on the new model at the thinking efforts you pick, and tells you what every run scored and what it cost.

拿你自己的问题去测。agent-eval 把你纠正过 agent 的真实时刻做成评测集，让新模型在你选的各档 effort 上重跑，告诉你每一次得了多少分、花了多少钱。

Part of the luoy2-skills plugin · Claude Code and Codex · MIT · runs on your computer and sends nothing to the author

luoy2-skills 插件的一部分 · Claude Code 和 Codex · MIT 许可 · 在你的电脑上运行，不向作者发送任何数据

Leaderboard scores keep climbing. Does your agent? 榜单分一版比一版高，你的 agent 呢？

Every release brings the same questions. Switch or stay? How should you use it? Which thinking effort, and what will it cost? Is it actually better than what you had?

每次有新模型，问题都是这几个：换不换？怎么用？effort 开到多少，要花多少钱？和原来的比，到底是不是更好？

Public benchmarks answer them for someone else’s tasks. A model can top the leaderboard and still feel worse in your repository: vaguer plans, more abstract answers, the same mistake you corrected last month.

公开榜单测的是别人的任务。一个模型可以刷到榜首，放进你的仓库却更难用：计划更空，回答更抽象，上个月纠正过的错又犯一次。

The test that answers your questions is built from your own problems.

能回答这些问题的测试，只能用你自己的问题来做。

Each question, answered on your own cases每个问题，都用你自己的题来回答

Switch or stay?换不换？
Run the new model and your current one on the same cases, the same snapshots and the same judges.新模型和现在用的模型，跑同一批题、同一个快照、同一对 judge。
Which thinking effort?effort 开多少？
Every effort level is its own row in the matrix, with its score and its cost per run.每一档 effort 在矩阵里单独一行，得分和每次花费并排摆着。
How should you use it?怎么用？
Compare solo, reviewed and forced-adoption runs, or lay a new AGENTS.md over the old snapshots and rerun the same cases.比较单独写、评审后改稿、强制采纳评审三种方式；也可以把新的 AGENTS.md 叠到旧快照上，同一批题重跑。
Better than what you had?比原来的强吗？
Keep the cases as a baseline and rerun them when the next model ships.题目留作基线，下个模型发布时再跑一遍。

Test models and effort on the mistakes your agents actually made 在你的 agent 真犯过的错上，测模型和 effort

Every case is a real moment when you corrected an agent. A candidate model gets the same instruction, the same facts and the repository as it was then, and is scored on whether it avoids the mistake. Use it to pick a model and effort for a role, to check whether a review step or a new AGENTS.md helps, and as a regression baseline when a new model ships.

每道题都是你纠正 agent 的一个真实时刻。候选模型拿到同样的指令、同样的背景事实，以及当时那一版仓库，按它能不能避开那次的错来打分。可以用来给某个角色选模型和 effort，检验加评审或改 AGENTS.md 有没有用，也可以在新模型发布时当回归基线。

What you get你会得到

Score and cost for every model, effort and delivery mode on your own cases, and a baseline to rerun when the next model ships.

你自己题目上每个模型、每档 effort、每种交付方式的得分和花费，外加一套基线，下个模型出来时直接重跑。

How it works怎么做

  1. Mine corrections. Every message you typed after an agent turn comes out of your Claude Code and Codex logs. A small model (Claude Haiku by default) labels which ones are corrections; no keyword list decides. You pick 3–5 of different kinds.

    挖出纠正。从 Claude Code 和 Codex 日志里取出你在 agent 回复之后打的每一句话，由小模型（默认 Claude Haiku）判断哪些是纠正，不靠关键词表。你从中挑 3–5 道不同类型的。

  2. Write and review each case. Your verbatim messages, the facts the agent knew, the exact commit recovered from the reflog, and a two-level Trap: the right direction, and done right. You mark every item on a review page.

    写题、审题。你的原话、agent 当时掌握的事实、从 reflog 找回的确切提交，外加两级判定：方向对，和做到位。你在审阅页上逐条确认。

  3. Isolate and calibrate. Each run gets a one-commit snapshot with no later history, no credentials and no memory files. Codex runs and every run that edits code go inside macOS sandbox-exec; a Claude planning run gets read-only tools. Before any model is scored, both judges, from different vendors, must fail the original wrong answer and pass the one you accepted.

    隔离、校准。每次运行只拿到一个提交的快照：没有之后的历史、没有凭据、没有记忆文件。Codex 的运行和所有要改代码的运行都放进 macOS 的 sandbox-exec；Claude 做计划题时只给只读工具。给模型打分之前，两个不同厂商的 judge 必须先判原来的错答案不过、你认可的答案过。

  4. Run the matrix. Models × thinking effort × delivery mode: solo, with a reviewer, or forced adoption of the review. Implementation cases are scored by the real fix’s own tests.

    跑矩阵。模型 × effort × 交付方式：单独写、评审后改稿、强制采纳评审。实现题用真实修复自带的测试计分。

  5. Report with cost. A pass needs both judges. Each run’s list-price cost covers the whole chain, reviewer and subagents included.

    带成本出报告。两个 judge 都判过才算通过。每次运行按标价计全链成本，评审和子 agent 都算在内。

What agent-eval found on our own problems agent-eval 在我们自己的问题上测出了什么

All from the author’s own repository. Planning: 3 real correction cases, 6 models, effort from medium to each model’s highest, 156 planning runs; a pass needs both judges. Implementation: 20 runs, stopped early, plus 12 smoke runs. The sample is small: read it as an example of what the report shows, not as a ranking of models.

数据全部来自作者自己的仓库。计划题：3 道来自真实纠正的题，6 个模型，effort 从 medium 到各模型的最高档，共 156 次运行，两个 judge 都判过才算通过。实现题：跑到 20 次就提前叫停，另有 12 次冒烟测试。样本很小，请把它看作报告长什么样的一个例子，不要当成模型排名。

More effort barely moved the score. The cost rose 2.7×. effort 越开越高，分数几乎没动，花费涨到 2.7 倍

Planning · 3 real cases · 156 runs计划题 · 3 个真实案例 · 156 次运行

Rubric score: for each run, the share of the case’s yes/no rubric items that both judges marked as met, averaged over the runs at that effort. Every level landed between 38% and 43%. All 6 models ran medium to max; only gpt-6-astra and gpt-6-sol ran at ultra, so that bar averages those two.

细则得分：每次运行中，两个 judge 都判为满足的是非细则占该题细则的比例，再对同一档 effort 的所有运行取平均。各档都在 38% 到 43% 之间。6 个模型都跑了 medium 到 max；只有 gpt-6-astra 和 gpt-6-sol 跑了 ultra，所以 ultra 那一栏只是这两个模型的平均。

A reviewer tripled the cost and didn’t raise the score 加一轮评审，成本三倍，分数没涨

Planning · solo vs. reviewed runs计划题 · 单独写对比评审后改稿

On one case the reviewer pointed to the right direction in 24 of 26 runs, and after revising none passed. What failed was the writing model acting on the advice, not the review itself.

有一道题，评审员 26 次里有 24 次指出了正确方向，改稿之后仍然一次都没过。卡住的是写稿的模型没有照着改，不是评审本身没用。

A cheap model tied an expensive one 便宜模型和贵模型打平

Planning · average over each model’s runs计划题 · 每个模型全部运行的平均

Each cost is the average over all of that model’s runs, solo and reviewed, review round included.

花费是该模型全部运行（单独写和加评审）的平均，评审那一轮也算在内。

The plan mattered more than the model or the effort 计划比模型、比 effort 都要紧

实现题里有一道带 42 个隐藏测试，候选模型停手之后才放进去；快照原样能过 3 个。通过的隐藏测试数：

Each planner wrote one plan per round, so this compares two plans, not two planners. On the second case (285 hidden tests; the snapshot passes 122), given the plan the author had approved, gpt-6-sol and gpt-6-astra both passed 267–270, at $2–6 and $10–17 per run.

每个计划模型每轮只写一份计划，所以这里比的是两份计划，不能说明哪个模型更会写计划。另一道题有 285 个隐藏测试（快照原样过 122 个），给定作者批准过的计划后，gpt-6-sol 和 gpt-6-astra 都过了 267–270 个，每次花费分别是 $2–6 和 $10–17。

No run did it the author’s way: 0 of 156 156 次运行，没有一次做到作者本人的做法

Planning · 3 real cases · 156 runs计划题 · 3 个真实案例 · 156 次运行

All three cases turned on the author’s own engineering preferences, and none of them was written down in the repository or its rules. The report’s reading: the lever is writing those preferences into AGENTS.md, not more effort or another reviewer. questionnaire-review does that writing, from the options you override.

三道题考的都是作者个人的工程偏好，而这些偏好在仓库和规范里一个字都没写。报告的判断是：杠杆在于把偏好写进 AGENTS.md，而不是加 effort、加评审。questionnaire-review 做的就是这件事：从你改选的地方把偏好写成规则。

After the preferences were written in, a rerun of the best setup got the direction right on 2 of the 3 cases and still reached “done right” 0 of 6 times. That rerun is in-sample: 2 runs per case, on the same cases the rules came from.

把偏好写进规范后重跑最好的组合：方向上 3 道题对了 2 道，「做到位」仍是 0/6。这是样本内测试：每题只跑 2 次，规则也正是从这几道题总结出来的。

The mining step was checked too: on 4 sessions with known corrections (1,747 messages) it found all 5 correction moments, at about $0.004 per message.

找题这一步也核对过：在 4 个已知有纠正的会话（1,747 条消息）上，它找回了全部 5 个纠正时刻，每条消息约 $0.004。

agent-eval runs where your logs are: Claude Code or Codex on your own computer. In claude.ai chat or Cowork the skill loads, but it can reach neither your logs nor the command-line tools.

agent-eval 要在日志所在的地方运行：你自己电脑上的 Claude Code 或 Codex。在 claude.ai 网页聊天或 Cowork 里，skill 能加载，但既读不到本机日志，也调不了命令行工具。

Your logs stay on your computer 日志留在你自己的电脑上

No server, no account, no telemetry, and nothing is sent to the author. A step that calls an AI model puts only what is listed below into the prompt, and sends it to the provider you chose for that step through your own claude or codex login, like any prompt you type, or through your own model gateway if you set one.

没有服务器、没有账号、没有遥测，也不向作者发送任何数据。需要调用模型的步骤，只把下面列出的内容放进提示词，用你自己的 claude 或 codex 登录发给你为这一步选的服务商，和你平时输入提示词一样；如果你设了自己的模型网关，就经过网关。

The model gateway is off unless your agent-eval config sets gateway. The plugin never supplies a gateway address. The providers handle what they receive under their own terms, as they do your other prompts.

npx skills is Vercel’s installer. By default it reports each install (repository, skill and agent names) to skills.sh; the DISABLE_TELEMETRY=1 in the copied text turns that off. The plugin route doesn’t use it.

npx skills 是 Vercel 的安装工具，默认会向 skills.sh 报告一次安装（仓库名、skill 名、agent 名）。复制内容里的 DISABLE_TELEMETRY=1 把它关掉。插件方式不经过它。
